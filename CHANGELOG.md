# Changelog

## Unreleased
- Release 1 UI and facility talent search. **Backend:** migration `0007` (`professionals.discoverable`, `talent_refs`, `talent_invitations`); facility talent search under `/organizations/:orgId/talent` returning anonymized cards (ADR 0005) with optional job matching/ranking, invitations to apply, professional-side discoverability and invitation endpoints; applying marks the invitation applied. **Frontend:** `packages/api-client` (typed fetch client), `packages/ui` (accessible components, honest credential/eligibility/ranking displays, facility time-zone helpers, shared sign-in/MFA), `apps/web` (Next 15: public pages, auth, professional area, facility area incl. jobs/shifts/candidates/talent, notifications, account, support) and `apps/admin` (Next 15: staff sign-in with MFA, dashboard, facility and credential review, users, marketplace oversight, audit log, configuration, support). Both apps build for production. Tests: 255 backend, 28 UI (with automated accessibility checks), 7 client. **Not verified:** the UI has not been exercised in a real browser (none was available) and no browser end-to-end or manual accessibility testing has been done.
- Milestone 6 (backend): migration `0006` (`state_configurations`, `support_tickets`, `support_ticket_messages`, `support_updates` notification category). Platform operations API: dashboard (sections filtered by permission), audit-log search with filters and pagination, user search/detail and suspend/reactivate (revokes sessions; platform users protected), job oversight with audited pause/close/cancel interventions, organization lookup, per-state enable/disable enforced at publish and in search, request metrics. Support workflow (tickets, staff queue, internal notes, assignment, status, notifications). Hardening: CSP/CORP/permissions-policy/HSTS headers, credentialed CORS allowlist, global per-IP rate limit, structured request logging that excludes bodies/queries/headers, `/ready`, `requirePlatformMember`. Validation: end-to-end Release 1 journey test, anonymous-access sweep over 47 endpoints, log-secrecy test, dump/restore test on the embedded database. New permissions `admin.marketplace_oversight`, `admin.user_manage`. Docs: security baseline, operations runbook, acceptance matrix, endpoint index, ADR 0004 (row-level security deferred). **Not done:** row-level security, OpenAPI document, web/admin UI and browser tests, alerting wiring, restore drill on real PostgreSQL, shared rate-limit store, email provider and private-bucket adapters.
- Milestone 5 (backend): migration `0005` (`applications`, `application_shifts`, `application_events`, `candidate_matches`, `notifications`, `notification_preferences`, `platform_settings`). Direct applications (`POST /jobs/:id/apply`, `/professionals/me/applications`), facility candidate review (`/organizations/:orgId/jobs/:jobId/candidates`, `/applications`), application state machine, eligibility engine (`eligibility-v1`) separate from explainable ranking (`ranking-v1`, weights in platform settings via `/admin/settings/ranking-weights`), decision-point match snapshots, in-app + best-effort email notifications with per-category email preferences (`/notifications`), and notifications for organization and credential review decisions. See ADR 0003. Offers and acceptance are refused unless the candidate is `eligible`. Not built: facility search of professionals who have not applied, interview scheduling, offer terms, assignments.
- Milestone 4 (backend): migration `0004` (`jobs`, `job_requirements`, `shifts`, `job_events`, composite tenant foreign keys). Facility job API under `/organizations/:orgId/jobs`: create/edit drafts, explicit mandatory/preferred license and certification requirements, shifts (future-dated, max 24h, offset required), lifecycle `draft → published ⇄ paused → filled | closed | cancelled` with history. Publishing needs `jobs.publish`, an approved organization, a real description, valid references, requirements (or an explicit "no credential requirements" statement) and, for non-permanent roles, at least one future open shift. Structural fields and requirements freeze after publishing; closing/cancelling cancels open shifts. Professional opportunity search `/jobs` (filters: text, profession, specialty, state, employment type, pay, shift window; allowlisted sort; pagination) and job detail, showing only listable jobs. Search is plain filtering: no eligibility or ranking (Milestone 5). Separate `shift_requirements` table not built; shifts inherit job requirements.
- Milestone 3 (backend): migration `0003` (professions/specialties with placeholder seed, professionals, education, experience, preferences, availability, `credentials`, `credential_documents`, `credential_verifications`). Professional self-service API (`/professionals`), computed profile completeness (separate from verification), credential records with encrypted numbers, private document upload/delete with signed short-lived download links, credential review queue/detail/decision endpoints with honest verification labels, expiry derived from dates, taxonomy read and admin endpoints. New env vars `FIELD_ENCRYPTION_KEY`, `FILE_STORAGE_DIR`. See ADR 0002. No web UI yet; no facility access to credentials by design.
- Milestone 2 (backend): migration `0002` (organization profile fields, `organization_reviews` history, invitation hardening, `facilities` / `facility_locations` / `departments` with composite tenant foreign keys). Facility submit-for-review with a backend state machine (`draft/needs_information → submitted → under_review → approved | rejected | needs_information`, `approved ⇄ suspended`); reasons required for rejections, information requests and suspensions; profile locked while under review. Admin review queue (paginated, allowlisted sort), detail view (audited) and decision endpoint. Facility/location/department CRUD gated to approved organizations. Invitations (hashed single-use tokens, address-bound acceptance, supersede/revoke) and member role change/removal with a privilege-escalation guard (`canGrantRole`). Not yet built: web/admin UI for these flows, in-app/email notification of decisions (Milestone 5; facilities currently see decisions via `GET /organizations/:orgId/reviews`).
- Milestone 0: repository audit, ERD draft, ASSUMPTIONS.md, AGENTS.md.
- Milestone 1 (in progress): npm workspace; `@bsm/permissions` (org + platform RBAC); backend foundations (request IDs, error shape, validation, redacting logger, security headers, Origin check); migration `0001` (users, sessions, MFA, user tokens, organizations, members, invitations, append-only audit log); auth (register, email verification, login with lockout and rate limits, logout, password reset, TOTP MFA); organization create/read/update/members with tenant isolation; admin lookup + audit-log read behind MFA; `create-admin` and `migrate` scripts.
